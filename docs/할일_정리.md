## 할 일 7. 청킹 (답변 단위 분할)

- **원칙**: 문서 전체를 자르는 것이 아니라, **질문이 들어왔을 때 답이 될 만한 단위**로 나눔.
- **실행**: `python run_chunk.py`
- **입력**: `data/processed/{id}_clean.txt` + `{id}.meta.json`
- **처리**: 섹션 헤더(제1조, 1. 개설목적, 가. 안내 등) 감지, 목표 크기(약 550자) 단위로 병합
- **결과**: 카테고리별 폴더에 JSON 저장 — `data/processed/chunks/{category}/{doc_id}.json`
- **구성**: `app/ingest/chunking.py`

**현재 생성된 청크(문서별)**

| doc_id | category | chunks |
|--------|----------|--------|
| academic_001 | academic | 1598 |
| academic_002 | academic | 1650 |
| calendar_001 | calendar | 95 |
| calendar_002 | calendar | 96 |
| scholarship_001 | scholarship | 2 |
| scholarship_002 | scholarship | 7 |
| scholarship_003 | scholarship | 122 |
| scholarship_004 | scholarship | 122 |
| scholarship_005 | scholarship | 122 |
| faq_001 | faq | 11 |
| faq_002 | faq | 8 |

**청크 JSON 형식**

```json
{
  "chunk_id": "scholarship_001_chunk_01",
  "doc_id": "scholarship_001",
  "title": "장학금 지급 규정",
  "category": "scholarship",
  "section": "지급기준",
  "text": "제3조(지급기준) 성적장학금은 ..."
}
```

## 할 일 8. ChromaDB 적재 및 검색

- **역할**: 청크를 벡터 DB에 넣어, 질문과 유사한 문단을 검색할 수 있게 함.
- **실행 (적재)**: `python run_ingest_chroma.py`  
  - 전제: `run_chunk.py`로 청크 JSON이 이미 생성되어 있어야 함.
  - 동작: `data/processed/chunks/` 아래 모든 JSON을 읽어 ChromaDB에 임베딩 후 저장.
- **저장 위치**: `data/chroma_db/` (PersistentClient)
- **컬렉션**: `yu_docs` (이름 고정)
- **임베딩 모델**: `paraphrase-multilingual-MiniLM-L12-v2` (한글 포함)

**코드 위치**

- `app/retrieval/chroma_client.py` — 클라이언트·컬렉션·임베딩 함수
- `app/retrieval/chroma_ingest.py` — 청크 로드 후 ChromaDB 적재
- `app/retrieval/chroma_search.py` — 유사도 검색 (질문 문자열, n_results, category 필터)

**검색 예시 (코드)**

```python
from app.retrieval.chroma_search import search
results = search("장학금 중복 수혜 가능한가요?", n_results=5)
# 카테고리 한정
results = search("수강신청 기간이 언제예요?", n_results=3, category="academic")
```

**의존성**: `requirements.txt`에 `chromadb`, `sentence-transformers` 추가됨.  
첫 실행 시 임베딩 모델 다운로드로 시간이 걸릴 수 있음.

## 할 일 9. 시간표(academic) 온톨로지(트리플) 구축 및 조회

- **목표**: 시간표 질문(교수/과목/요일/대학 등)을 **문서 유사도 검색(RAG)** 대신 **관계 기반 조회**로 정확히 응답
- **입력**: `data/processed/chunks/academic/*.json`
- **출력**: `data/ontology/teaches.json`
- **내용(현재 구현)**:
  - 트리플(수업 슬롯) 단위로 저장: `교수(subject) -[teaches]-> 과목(object)` + `day/time_range/room/title/doc_id`
  - 다중 조건 조회(요일 + 대학(강의실 접두어) 등) 지원
- **실행**
  - 트리플 생성: `python run_build_ontology.py`
  - 조회: `python run_ontology_query.py`
    - 교수 → 수업: `python run_ontology_query.py 천양하`
    - 과목 → 일정: `python run_ontology_query.py --course "데이터베이스"`
    - 조합(자연어): `python run_ontology_query.py "무도대학 수요일 수업"`
- **코드 위치**
  - `app/ontology/triples.py`
  - `run_build_ontology.py`
  - `run_ontology_query.py`

## 할 일 10. Neo4j(그래프 DB) 동기화 및 그래프 조회

- **목표**: 온톨로지 트리플을 Neo4j에 적재해 **Graph 형태 시각화/쿼리(Cypher)** 로 조회
- **의존성**: `requirements.txt`에 `neo4j` 추가됨
- **동기화**
  - 실행: `python run_neo4j_sync.py`
  - 환경 변수(권장): `NEO4J_URI`, `NEO4J_USER`, `NEO4J_PASSWORD`
  - 환경 변수가 없거나 비어있으면 실행 중 비밀번호 입력 가능하도록 처리됨
- **조회**
  - `run_ontology_query.py`는 Neo4j 연결 가능 시 자동으로 Neo4j에서 조회(`[*Neo4j]` 표기)
  - Neo4j Browser에서 그래프 형태로 보려면 값이 아니라 노드/관계를 반환:
    - 예: `MATCH (p:Professor {name:\"천양하\"})-[t:TEACHES]->(c:Course) RETURN p,t,c;`
- **문서**
  - `docs/neo4j_setup.md`
- **코드 위치**
  - `app/ontology/neo4j_graph.py`
  - `run_neo4j_sync.py`
